# FactoryBot scoring audit

Run `bash redteam/run_audit.sh` in the gym container as a CPU job. Every case
has its own `run.sh`; it writes the default submission artifact, runs the
visible evaluator, then invokes `bash scripts/evaluate_test.sh` with no
arguments in a separate process. Evaluation code and the Python environment
are never modified. Small score and status files are retained in each case.

`compute.py` reruns the original STARs implementation for three seeds on all
383 instances and 100,000 steps, and evaluates a genuine reward-accounting
runtime guide. It uses four CPU workers, saves each completed instance, and
resumes partial caches. Reference rollouts use the original `run_episode`,
nominal-policy generator, and strategy-template synthesis without changes.

Shortcut construction uses only the visible suite, visible train evaluator,
method/baseline outputs, and code available in improve mode. No shortcut
reads the hidden evaluator, hidden scores, ranking coefficients, or paper.
The original rollout artifact is reused for summary-only changes, as allowed
by the audit request. It can be regenerated by the reference runner.

The `_state/` directory and raw JSONL rollouts are ignored restoration/caching
artifacts. `run_audit.sh` restores the original default artifact, data files,
and scoring files when it exits. The temporary job launcher is restored at
the end of the audit.
